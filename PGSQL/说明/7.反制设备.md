# 反制设备表和函数说明

本文档对应 `PGSQL/函数/7.反制设备.sql`，用于说明低空无人机反制设备、设备缓冲区、实时点位预警通知相关表和函数。

## 表结构

### bo_counter_device

反制设备基础表，存储设备本身的信息、空间点位和作用半径。

| 字段 | 含义 |
| --- | --- |
| `id` | 设备主键 ID |
| `project_id` | 所属项目 ID |
| `create_user` | 创建人 |
| `create_time` | 创建时间 |
| `update_user` | 更新人 |
| `update_time` | 更新时间 |
| `del_flag` | 是否删除，`false` 未删除，`true` 已删除 |
| `status` | 状态，`1` 启用，`0` 停用 |
| `device_code` | 设备编号 |
| `device_name` | 设备名称 |
| `device_type` | 设备类型，例如侦测、干扰、诱骗、捕获、综合 |
| `device_model` | 设备型号 |
| `manufacturer` | 厂商 |
| `contact_name` | 联系人 |
| `contact_phone` | 联系电话 |
| `address` | 设备安装地址 |
| `lng` | 经度 |
| `lat` | 纬度 |
| `altitude` | 设备海拔或安装高度，单位米 |
| `action_radius_m` | 反制作用半径，单位米 |
| `warning_radius_m` | 预警半径，单位米 |
| `notice_radius_m` | 通知半径，单位米 |
| `min_alt` | 设备有效最低高度，单位米 |
| `max_alt` | 设备有效最高高度，单位米，空表示不限制 |
| `response_level` | 响应等级，数值越小等级越高 |
| `remark` | 备注 |
| `attrs` | 扩展属性，JSON 格式 |
| `geom` | 设备空间点位，PostGIS `Point`，坐标系 EPSG:4326 |

核心字段：

```text
geom              设备点位
action_radius_m   反制作用半径
warning_radius_m  预警半径
notice_radius_m   通知半径
min_alt/max_alt   设备生效高度范围
```

### bo_counter_device_warning_notice

反制设备实时点位预警通知表。实时无人机点位进入设备作用区、预警区或通知区后，检测函数会写入一条通知记录。

| 字段 | 含义 |
| --- | --- |
| `id` | 通知记录主键，自增 |
| `project_id` | 项目 ID |
| `device_id` | 命中的反制设备 ID |
| `device_code` | 命中的设备编号 |
| `device_name` | 命中的设备名称 |
| `uav_id` | 无人机 ID |
| `track_id` | 轨迹 ID |
| `warning_type` | 预警类型，`action` 作用区，`warning` 预警区，`notice` 通知区 |
| `warning_level` | 预警等级，`1` 最高，`2` 较高，`3` 一般 |
| `warning_msg` | 预警消息 |
| `distance_m` | 无人机点位到设备的距离，单位米 |
| `point_lng` | 无人机实时经度 |
| `point_lat` | 无人机实时纬度 |
| `point_alt` | 无人机实时高度，单位米 |
| `point_time` | 无人机点位时间 |
| `notify_status` | 通知状态，`0` 待通知，`1` 已通知，`2` 忽略 |
| `create_time` | 通知记录创建时间 |
| `device_geom` | 命中的设备点位 |
| `point_geom` | 无人机实时点位 |
| `buffer_geom` | 命中的缓冲区范围 |
| `attrs` | 扩展属性，JSON 格式 |

### gis_counter_device_{project_id}

项目反制设备表，由 `gis_counter_device_project` 动态生成。表名中的 `{project_id}` 替换为实际项目 ID，例如：

```text
gis_counter_device_zhengzhou_demo
```

该表是从 `bo_counter_device` 按项目范围筛选出来的设备副本，主要用于项目内查询、GeoServer 展示和空间检测。

| 字段 | 含义 |
| --- | --- |
| `id` | 设备 ID |
| `source_project_id` | 原设备所属项目 ID |
| `device_code` | 设备编号 |
| `device_name` | 设备名称 |
| `device_type` | 设备类型 |
| `device_model` | 设备型号 |
| `manufacturer` | 厂商 |
| `contact_name` | 联系人 |
| `contact_phone` | 联系电话 |
| `address` | 安装地址 |
| `lng` | 经度 |
| `lat` | 纬度 |
| `altitude` | 设备高度 |
| `action_radius_m` | 作用半径 |
| `warning_radius_m` | 预警半径 |
| `notice_radius_m` | 通知半径 |
| `min_alt` | 有效最低高度 |
| `max_alt` | 有效最高高度 |
| `response_level` | 响应等级 |
| `create_time` | 项目表生成时间 |
| `geom` | 设备点位 |

## 函数说明

### gis_counter_device_project

根据项目 ID 和项目范围 GeoJSON，生成项目专属反制设备表。

```sql
SELECT * FROM public.gis_counter_device_project(
    'zhengzhou_demo',
    '{"type":"Polygon","coordinates":[[[113.0,34.5],[114.0,34.5],[114.0,35.0],[113.0,35.0],[113.0,34.5]]]}'
);
```

输出包含状态码、消息、生成表名和导入设备数量。

### gis_get_counter_device_project

查询项目反制设备表，可按设备类型过滤。

```sql
SELECT * FROM public.gis_get_counter_device_project('zhengzhou_demo', NULL);
SELECT * FROM public.gis_get_counter_device_project('zhengzhou_demo', '侦测,干扰');
```

### gis_counter_device_buffer

动态生成反制设备作用区、预警区、通知区缓冲面。

```sql
SELECT * FROM public.gis_counter_device_buffer('zhengzhou_demo', NULL, true);
```

返回的 `buffer_type` 含义：

| 值 | 含义 |
| --- | --- |
| `action` | 反制作用区 |
| `warning` | 预警区 |
| `notice` | 通知区 |

### gis_counter_device_check_point_buffer

检测实时无人机点位是否进入反制设备缓冲区。命中后自动写入 `bo_counter_device_warning_notice`。

```sql
SELECT * FROM public.gis_counter_device_check_point_buffer(
    'zhengzhou_demo',
    '{"type":"Point","coordinates":[113.405861,34.769437,120]}',
    'uav_001',
    'track_001',
    true
);
```

预警等级规则：

| 命中范围 | `warning_type` | `warning_level` |
| --- | --- | --- |
| 进入作用半径 | `action` | `1` |
| 进入预警半径 | `warning` | `2` |
| 进入通知半径 | `notice` | `3` |

## 表和函数是否分开

当前设计是表和函数分开：

| 类型 | 名称 | 作用 |
| --- | --- | --- |
| 表 | `bo_counter_device` | 存设备基础数据和半径 |
| 表 | `bo_counter_device_warning_notice` | 存实时预警通知记录 |
| 动态表 | `gis_counter_device_{project_id}` | 存项目范围内设备副本 |
| 函数 | `gis_counter_device_project` | 生成项目设备表 |
| 函数 | `gis_get_counter_device_project` | 查询项目设备 |
| 函数 | `gis_counter_device_buffer` | 动态生成缓冲区 |
| 函数 | `gis_counter_device_check_point_buffer` | 实时点位预警检测并写入通知 |

## 设备表和缓冲区是否合表

可以合表，但不推荐把设备点位和缓冲区面长期强绑定在同一张主业务表。

合表方式示例：

```sql
geom              geometry(Point, 4326),
action_buffer     geometry(Polygon, 4326),
warning_buffer    geometry(Polygon, 4326),
notice_buffer     geometry(Polygon, 4326)
```

优点：

- 查询简单，前端展示设备和缓冲区时一张表即可读取。
- 缓冲区已经预生成，实时检测时不用每次计算 `ST_Buffer`。
- 便于 GeoServer 发布图层。

缺点：

- 数据冗余，缓冲区是由点位和半径计算出来的派生数据。
- 容易不一致，修改点位或半径后必须同步更新缓冲区。
- 表会变重，多个 Polygon 字段会增加存储和空间索引成本。
- 后续新增缓冲类型时需要改表结构。

推荐方案：

- `bo_counter_device` 存设备基础数据。
- `gis_counter_device_buffer` 动态生成缓冲区。
- 如果实时性能压力较大，再新增 `bo_counter_device_buffer` 作为缓冲区缓存表。
- `bo_counter_device_warning_notice` 专门存预警通知记录。

## 定时清理

清理轨迹和日志使用 `PGSQL/函数/9.3清空表日志.sql` 中的函数：

```sql
SELECT * FROM public.gis_cleanup_track_log_tables(7, true, true);
```

试运行，只统计预计清理数量。

```sql
SELECT * FROM public.gis_cleanup_track_log_tables(7, false, true);
```

正式清理，保留最近 7 天。

自动定时方式可以选择：

- `pg_cron`
- Windows 任务计划程序
- Linux `crontab`
- 应用服务定时任务
- Jenkins、xxl-job、Airflow、Kubernetes CronJob 等外部调度平台

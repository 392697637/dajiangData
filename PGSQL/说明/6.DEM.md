## 2. 建表说明

`public.gis_dem_henan` 不建议手工 `CREATE TABLE` 创建空表。

正式流程是使用 `raster2pgsql` 根据 DEM tif 自动生成建表 SQL，并导入数据。这样可以同时完成：

- 创建 DEM 栅格表
- 按 `256x256` 切片写入栅格数据
- 创建空间索引
- 添加 PostGIS Raster 约束
- 执行 `VACUUM ANALYZE`

表名说明：

| 名称 | 说明 |
| --- | --- |
| `public` | PostgreSQL schema 名称 |
| `gis_dem_henan` | DEM 栅格主表名称 |
| `public.gis_dem_henan` | 完整表名，后续 DEM 查询函数默认读取该表 |

字段说明：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `rid` | `integer` | 栅格瓦片主键，`raster2pgsql` 自动生成 |
| `rast` | `raster` | DEM 栅格瓦片数据，核心字段 |
| `filename` | `text` | 可选字段，使用 `raster2pgsql -F` 时生成 |
| `created_at` | `timestamp` | 可选字段，`raster2pgsql` 默认不生成，需要时可后续添加 |

核心必需字段只有：

```text
rid
rast
```

如果需要在导入后增加入库时间字段：

```sql
ALTER TABLE public.gis_dem_henan
ADD COLUMN IF NOT EXISTS created_at timestamp without time zone DEFAULT now();
```

如果需要导入时记录文件名，在 `raster2pgsql` 参数中增加 `-F`。

### 4.1 SRID 确定逻辑

`raster2pgsql -s` 后面的 SRID 必须填写 **tif 文件自身的真实坐标系**，不是数据库坐标系，也不是电子围栏坐标系。

判断逻辑：

```text
1. 先查看 tif 的真实坐标系
2. 如果 tif 是 EPSG:32650，就使用 -s 32650
3. 如果 tif 是 EPSG:4326，才使用 -s 4326
4. raster2pgsql -s 只设置 SRID 标签，不会把坐标重投影
5. 如果 DEM 和电子围栏坐标系不同，在查询时使用 ST_Transform 做转换
```

当前河南 DEM：

```text
E:\DEM\HENAN.tif
EPSG:32650 - WGS 84 / UTM zone 50N
单位：米
```

所以当前导入命令应使用：

```cmd
raster2pgsql -s 32650 -I -C -M -t 256x256 "E:\DEM\HENAN.tif" public.gis_dem_henan > E:\DEM\gis_dem_henan.sql
```

电子围栏当前使用 `EPSG:4326`，与 DEM 不同。后续叠加判断时应转换坐标：

```sql
ST_Transform(电子围栏geom, 32650)
```

展示 DEM 范围给前端时，可以转回经纬度：

```sql
ST_Transform(DEM范围, 4326)
```

### 4.2 SRID 写错的后果

`raster2pgsql -s` 不会改变 tif 的坐标值，只会给入库后的 raster 设置 SRID 标签。

如果把真实为 `EPSG:32650` 的 DEM 错误写成 `-s 4326`，会造成：

- DEM 坐标仍然是米制投影坐标，但数据库认为它是经纬度
- 查询范围会出现几十万、几百万这样的坐标值
- DEM 范围不会落在河南经纬度范围内
- 与电子围栏 `4326` 做 `ST_Intersects`、`ST_Contains` 等空间判断会错误
- 点高程查询可能查不到值，或者查到错误瓦片
- `ST_Transform` 可能得到错误位置，甚至转换失败
- 前端地图展示会偏移到错误位置或完全不可见
- 后续坡度、剖面、裁剪、统计结果都不可信

错误示例：

```text
POLYGON((-110205.50849306703 3473458.800959141,-110205.50849306703 4029549.648151288,467250.0472186846 4029549.648151288,467250.0472186846 3473458.800959141,-110205.50849306703 3473458.800959141))
```

这个范围不是经纬度，而是 `EPSG:32650` 的米制投影坐标。如果它被标记成 `4326`，就说明 SRID 用错了。

处理方式：

```text
1. 不建议继续使用错误 SRID 的表做业务判断
2. 用 tif 真实 SRID 重新导入新表
3. 当前河南 DEM 应使用 -s 32650
4. 电子围栏仍保持 4326
5. 业务查询时用 ST_Transform 对齐坐标系
```

### 4.3 使用 QGIS 转换为 EPSG:4326

如果希望 DEM 入库后直接使用 `EPSG:4326`，可以先在 QGIS 中把 tif 从 `EPSG:32650` 重投影为 `EPSG:4326`，再导入数据库。

适用场景：

- 主要用于和电子围栏 `4326` 叠加
- 主要用于前端地图展示
- 希望 DEM 表范围直接显示经纬度

注意：如果后续要做坡度、距离、面积、剖面等米制计算，保留 `EPSG:32650` 更合适。

QGIS 操作步骤：

```text
1. 打开 QGIS
2. 加载 E:\DEM\HENAN.tif
3. 右键图层 HENAN.tif
4. 选择：导出 -> 另存为...
5. 格式选择：GeoTIFF
6. CRS / 坐标参考系选择：EPSG:4326 - WGS 84
7. 输出文件：E:\DEM\HENAN_4326.tif
8. 点击确定，等待转换完成
```

转换完成后，使用 `4326` 导入新表：

```cmd
raster2pgsql -s 4326 -I -C -M -t 256x256 "E:\DEM\HENAN_4326.tif" public.gis_dem_henan_4326 > E:\DEM\gis_dem_henan_4326.sql
```

导入数据库：

```cmd
set PGPASSWORD=Ktd@postSQL@2026!@#
psql -h 192.168.110.6 -p 5432 -U zhuoyi -d ktd_lx_2026gis -f E:\DEM\gis_dem_henan_4326.sql
```

验证 SRID：

```cmd
psql -h 192.168.110.6 -p 5432 -U zhuoyi -d ktd_lx_2026gis -c "SELECT ST_SRID(rast) AS srid FROM public.gis_dem_henan_4326 LIMIT 1;"
```

正常应返回：

```text
4326
```

验证范围：

```cmd
psql -h 192.168.110.6 -p 5432 -U zhuoyi -d ktd_lx_2026gis -c "SELECT ST_AsText(ST_Envelope(ST_Collect(ST_ConvexHull(rast)))) AS dem_extent FROM public.gis_dem_henan_4326;"
```

如果转换正确，范围应接近河南经纬度：

```text
经度：110 ~ 116
纬度：31 ~ 37
```

## 6. 参数说明

| 参数 | 说明 |
| --- | --- |
| `-s 4326` | 指定 DEM 坐标系 SRID。`4326` 表示 WGS 84 经纬度坐标系。 |
| `-I` | 为栅格列创建空间索引，提升空间查询性能。 |
| `-C` | 导入后添加栅格约束，例如 SRID、像元大小、范围、波段数量等。 |
| `-M` | 导入完成后执行 `VACUUM ANALYZE`，更新数据库统计信息。 |
| `-t 256x256` | 把 DEM 切片为 `256 x 256` 像元大小的瓦片存储，适合大范围 DEM 查询和局部加载。 |
| `"E:\DEM\HENAN_4326.tif"` | 输入 DEM 文件路径。建议使用英文路径并用双引号包裹。 |
| `public.gis_dem_henan` | 导入后的目标表名。`public` 是 schema，`gis_dem_henan` 是表名。 |
| `psql -h ... -p ... -U ... -d ...` | 连接 PostgreSQL 数据库并执行 `raster2pgsql` 生成的 SQL。 |
| `set PGPASSWORD=...&&` | 在 `cmd /c` 中临时设置数据库密码，避免 `psql` 交互输入密码。 |
| `|` | 管道符，把 `raster2pgsql` 输出的 SQL 传给 `psql` 执行。 |

如果是追加导入到已有表，可以增加 `-a`：

```powershell
cmd /c "set PGPASSWORD=Ktd@postSQL@2026!@#&& raster2pgsql -a -s 4326 -I -C -M -t 256x256 ""E:\DEM\HENAN_4326.tif"" public.gis_dem_henan | psql -h 192.168.110.6 -p 5432 -U zhuoyi -d ktd_lx_2026gis"
```

首次建表时不要加 `-a`。

## 8. 常见问题

### 8.1 Unable to read raster file

错误示例：

```text
ERROR: Unable to read raster file: E:\卓翼智能\数据\DEM\河南.tif
```

处理方式：

1. 用 `Test-Path` 检查文件是否存在。
2. 用 `gdalinfo` 检查 tif 是否能被 GDAL 读取。
3. 将文件复制到纯英文路径，例如 `E:\DEM\HENAN_4326.tif`。
4. 重新执行导入命令。

### 8.2 表已存在

如果首次导入时目标表已经存在，可以换表名。当前推荐流程已经使用新表：

```text
public.gis_dem_henan
```

如果确认要追加到已有表，使用 `-a`。

### 8.3 PowerShell 管道执行 psql 失败

错误示例：

```text
程序“psql.exe”无法运行: 容量小于当前大小。
参数名: requiredLength
```

这个错误通常不是数据库连接问题，也不是 DEM 文件读取问题。前面已经输出：

```text
Processing 1/1: E:\DEM\HENAN_4326.tif
```

说明 `raster2pgsql` 已经能读取 tif。问题多发生在 Windows PowerShell 管道处理大体量 SQL 输出时。

推荐按 `4.1 Windows 推荐执行方式` 重新生成 SQL 文件并导入。

如果要一条命令直接导入，可以使用：

```powershell
cmd /c "set PGPASSWORD=Ktd@postSQL@2026!@#&& raster2pgsql -s 4326 -I -C -M -t 256x256 ""E:\DEM\HENAN_4326.tif"" public.gis_dem_henan | psql -h 192.168.110.6 -p 5432 -U zhuoyi -d ktd_lx_2026gis"
```

如果要先生成 SQL 文件，再导入，使用：

```powershell
cmd /c "raster2pgsql -s 4326 -I -C -M -t 256x256 ""E:\DEM\HENAN_4326.tif"" public.gis_dem_henan > E:\DEM\gis_dem_henan.sql"
```

然后执行：

```powershell
cmd /c "set PGPASSWORD=Ktd@postSQL@2026!@#&& psql -h 192.168.110.6 -p 5432 -U zhuoyi -d ktd_lx_2026gis -f E:\DEM\gis_dem_henan.sql"
```

如果 SQL 文件很大，第二种方式更容易排查问题，也方便重复导入。

注意：不要在 Windows PowerShell 5 中直接使用下面写法生成 SQL 文件：

```powershell
raster2pgsql -s 4326 -I -C -M -t 256x256 "E:\DEM\HENAN_4326.tif" public.gis_dem_henan > E:\DEM\gis_dem_henan.sql
```

Windows PowerShell 5 的 `>` 可能会把文件保存成 UTF-16 LE，导入时报：

```text
ERROR: character with byte sequence 0xff 0xfe in encoding "GBK" has no equivalent in encoding "UTF8"
```

遇到这个错误时，删除旧的 `E:\DEM\gis_dem_henan.sql`，用 `cmd /c` 方式重新生成。

### 8.4 坐标系不确定

不要盲目写 `-s 4326`。应先通过 `gdalinfo` 查看 DEM 的真实坐标系。

如果 DEM 是米制投影坐标系，应填写对应 EPSG 编码。坡度、坡向等地形分析更适合使用米制投影数据。

### 10.5 点线面补充 DEM 高程

`gis_dem_elevation_geometry(geometry)` 是 6.1 的 geometry 分发入口。它会先按点/线/面判断几何类型，再转到 `gis_dem_elevation_point`、`gis_dem_elevation_line`、`gis_dem_elevation_polygon`。`gis_dem_elevation_base(geometry)` 仍然是底层核心入口。

点补高程：

```sql
SELECT ST_AsText(
    public.gis_dem_elevation_point(
        ST_SetSRID(ST_MakePoint(113.65, 34.76), 4326)
    )
) AS point_z;
```

```sql
SELECT ST_AsText(
    public.gis_dem_elevation_point(
        ST_GeomFromText('MULTIPOINT((113.65 34.76),(113.66 34.77))', 4326)
    )
) AS multipoint_z;
```

线/多线补高程：

```sql
SELECT ST_AsText(
    public.gis_dem_elevation_line(
        ST_GeomFromText('LINESTRING(113.60 34.70,113.65 34.76,113.70 34.80)', 4326)
    )
) AS line_z;
```

```sql
SELECT ST_AsText(
    public.gis_dem_elevation_line(
        ST_GeomFromText(
            'MULTILINESTRING((113.60 34.70,113.70 34.80),(113.62 34.72,113.68 34.78))',
            4326
        )
    )
) AS multiline_z;
```

面/多面补高程：

```sql
SELECT ST_AsText(
    public.gis_dem_elevation_polygon(
        ST_GeomFromText(
            'POLYGON((113.60 34.70,113.70 34.70,113.70 34.80,113.60 34.80,113.60 34.70))',
            4326
        )
    )
) AS polygon_z;
```

```sql
SELECT ST_AsText(
    public.gis_dem_elevation_polygon(
        ST_GeomFromText(
            'MULTIPOLYGON(((113.60 34.70,113.66 34.70,113.66 34.76,113.60 34.76,113.60 34.70)),((113.68 34.72,113.72 34.72,113.72 34.78,113.68 34.78,113.68 34.72)))',
            4326
        )
    )
) AS multipolygon_z;
```

支持类型：

| 函数 | 输入 | 输出 |
| --- | --- | --- |
| `gis_dem_elevation_geometry` | `Point/MultiPoint/LineString/MultiLineString/Polygon/MultiPolygon` | 自动分发到点/线/面入口 |
| `gis_dem_elevation_base` | `Point geometry` | 单点 DEM 高程值 |
| `gis_dem_elevation_base` | `Point/MultiPoint/LineString/MultiLineString/Polygon/MultiPolygon/GeometryCollection` | 对应 Z 几何 |
| `gis_dem_elevation_point` | `Point/MultiPoint geometry` | `PointZ/MultiPointZ` |
| `gis_dem_elevation_line` | `LineString/MultiLineString geometry` | `LineStringZ/MultiLineStringZ` |
| `gis_dem_elevation_polygon` | `Polygon/MultiPolygon geometry` | `PolygonZ/MultiPolygonZ` |
| `gis_dem_elevation_text_point` | `Point/MultiPoint WKT/EWKT/GeoJSON text` | `PointZ/MultiPointZ` |
| `gis_dem_elevation_text_line` | `LineString/MultiLineString WKT/EWKT/GeoJSON text` | `LineStringZ/MultiLineStringZ` |
| `gis_dem_elevation_text_polygon` | `Polygon/MultiPolygon WKT/EWKT/GeoJSON text` | `PolygonZ/MultiPolygonZ` |
| `gis_dem_elevation_text` | `WKT/EWKT/GeoJSON text` | 统一表结构，含 `result_geom` 和 `result_wkt` |

注意：

- 输入 geometry 没有 SRID 时按 `EPSG:4326` 处理。
- 已有 Z 值的输入会按 XY 查询 DEM，并用 DEM 高程生成新的 Z 值。
- 点不在 DEM 覆盖范围内时，补高程入口默认补 `0`。
- `Polygon` 支持外环和内环。
- 点/线/面 text 专用入口适合接口层接收前端 WKT、EWKT 或 GeoJSON 文本，并直接返回补高程后的 Z 几何。
- `gis_dem_elevation_text` 适合需要统一表结构返回的接口；如果后端已经有 geometry，优先直接调用 geometry 入口。

点/线/面 text 专用入口示例：

```sql
SELECT ST_AsText(public.gis_dem_elevation_text_point('POINT(113.65 34.76)')) AS point_text_z;
```

```sql
SELECT ST_AsText(public.gis_dem_elevation_text_line('SRID=4326;LINESTRING(113.60 34.70,113.70 34.80)')) AS line_text_z;
```

```sql
SELECT ST_AsText(
    public.gis_dem_elevation_text_polygon(
        '{"type":"Feature","properties":{"name":"demo"},"geometry":{"type":"Polygon","coordinates":[[[113.60,34.70],[113.70,34.70],[113.70,34.80],[113.60,34.80],[113.60,34.70]]]}}'
    )
) AS polygon_text_z;
```

## 11. 派生地形数据

脚本中可扩展生成三个派生栅格表：

| 表名 | 说明 |
| --- | --- |
| `public.gis_dem_henan_slope` | 坡度栅格 |
| `public.gis_dem_henan_aspect` | 坡向栅格 |
| `public.gis_dem_henan_hillshade` | 阴影地形栅格 |

示例：

```sql
SELECT ST_Slope(rast, 1, '32BF', 'DEGREES') FROM public.gis_dem_henan;
SELECT ST_Aspect(rast, 1, '32BF', 'DEGREES') FROM public.gis_dem_henan;
SELECT ST_HillShade(rast, 1, '8BUI', 315, 45) FROM public.gis_dem_henan;
```

坡度、坡向计算对坐标单位敏感。生产环境建议使用米制投影 DEM，或先将 DEM 预处理到合适投影后再入库。

## 12. 推荐流程

Windows 推荐只打开 PowerShell，然后逐条执行 `4.1 Windows 推荐执行方式` 中的命令。

```text
1. 将 DEM 放到英文路径：E:\DEM\HENAN_4326.tif
2. 打开 PowerShell，不需要手动切换到 CMD
3. 用 Test-Path 检查文件是否存在
4. 用 gdalinfo 检查 tif 是否可读取，并确认真实 SRID
5. 在目标数据库启用 postgis 和 postgis_raster 扩展
6. 删除旧的 E:\DEM\gis_dem_henan.sql
7. 用 cmd /c 重新生成 E:\DEM\gis_dem_henan.sql
8. 用 cmd /c 调用 psql -f 导入 SQL 文件
9. 查询 COUNT(*)、ST_SRID、ST_Extent 验证入库结果
10. 执行 PGSQL/函数/6.DEM.sql 创建项目查询函数
11. 使用点高程、面统计、线剖面函数进行业务调用
```

关键原则：

- 不要在 PowerShell 5 中直接使用 `raster2pgsql ... | psql ...`。
- 不要在 PowerShell 5 中直接使用 `raster2pgsql ... > E:\DEM\gis_dem_henan.sql`。
- Windows 下统一在 PowerShell 窗口中复制执行文档里的 `cmd /c "..."` 命令。

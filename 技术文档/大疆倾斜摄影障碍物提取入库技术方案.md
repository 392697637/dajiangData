# 大疆无人机倾斜摄影数据提取建筑障碍物入库及航线规划应用技术方案

> 版本：v1.0　|　适用环境：Windows + WebODM 2.9.6 + QGIS/OSGeo4W + PostgreSQL 17 + PostGIS 3.6
> 目标：从大疆无人机倾斜航飞成果中提取建筑/障碍物（轮廓+高度+类型），入库 PostgreSQL，用于无人机航线规划的净空避障与三维可视化叠加。

---

## 一、项目背景与目标

### 1.1 背景
无人机低空巡检/作业中，航线规划必须避开建筑物、树木、电线杆、塔吊等障碍物，否则存在飞行碰撞风险。传统做法依赖人工目视勾绘，工作量大、易漏判、难更新。

### 1.2 目标
- 从大疆倾斜摄影成果（正射 DOM、倾斜模型、点云）中**自动提取建筑障碍物**；
- 得到每个障碍物的**平面轮廓、相对高度、类型**；
- 入库 **PostgreSQL/PostGIS**，形成统一空间图层 `gis_obstacles`；
- 供**航线规划净空检查**、**避障**、**电子围栏联动**、**Cesium 三维叠加**使用。

### 1.3 成果与分工
| 数据 | 角色 | 解决什么问题 |
|---|---|---|
| 正射影像 DOM | 识别"是什么类型" | 地物分类、目视核对底图 |
| 倾斜模型 / DSM | 量"多高、多大轮廓" | 高度差分、三维展示 |
| 点云 LAS | 最准的高度/细小物 | 高精度障碍物、电力线/杆塔提取 |

## 二、总体技术架构

> 原有架构图保留，用于说明高度栅格及下游应用；三类数据独立处理的详细步骤见 4.1、4.2、4.3，不要求共同输入。

```
┌─────────────┐    ┌──────────────────┐    ┌──────────────────────┐
│ 大疆航飞数据 │ → │  WebODM 摄影测量  │ → │ DSM / DTM / DOM / 点云│
│ (多镜头影像) │    │  (空三+密集匹配)  │    └──────────┬───────────┘
└─────────────┘                                      │
                                                      ▼
                    ┌───────────────────────────────────────────┐
                    │  高度建模：nDSM = DSM − DTM（相对高度）      │
                    │  障碍物提取：阈值二值化 → 矢量化 → 分类       │
                    └───────────────────┬───────────────────────┘
                                        ▼
              ┌─────────────────────────────────────────────────┐
              │  PostgreSQL / PostGIS：gis_obstacles 空间表       │
              │  （footprint + height + obstacle_type + 索引）    │
              └───────────────────┬─────────────────────────────┘
                                  ▼
        ┌──────────────┬───────────────────┬─────────────────────┐
        ▼              ▼                   ▼                     ▼
   净空检查     航线避障约束        电子围栏联动        Cesium 三维叠加
  ST_3DIntersects  gis_astar_3d     gis_electric_fence  3D Tiles + 白膜
```

### 核心原理（一句话）
> 倾斜模型量高度（DSM−DTM=nDSM）→ 高于阈值圈成多边形 → 分类型存表 → 规划净空查询 → Cesium 叠加显示。

## 三、技术路线

1. **数据采集**：大疆无人机多镜头倾斜航飞，获取带 POS 坐标的影像。
2. **摄影测量处理（WebODM）**：空三解算 → 密集匹配 → 输出 DSM、DTM、DOM、点云。
3. **高度建模**：DSM − DTM（或点云滤波生成）得 nDSM 相对高度。
4. **障碍物提取**：nDSM 高度阈值二值化 → 矢量化 → 单体过滤 → 类型判定。
5. **空间入库**：raster2pgsql 栅格入库 + PostGIS 矢量化 → `gis_obstacles` 表。
6. **规划应用**：净空检查、避障约束、围栏联动。
7. **三维叠加**：坐标统一 4326，GeoJSON 白膜 / pg2b3dm 3D Tiles 叠加到倾斜模型。

---

### 3.1 原有上游流程：数据采集（大疆航飞）

- 载荷：大疆倾斜相机（多镜头：下视 + 前/后/左/右），或下视+少量倾斜。
- 航飞要求：保证**重叠度**（航向≥80%、旁向≥60%，倾斜模型建议更高），低空采集保证 DSM 分辨率。
- 成果：全部镜头影像（JPG）+ POS/坐标信息，整理到 `D:\drone_images`。

### 3.2 原有上游流程：摄影测量处理（WebODM 2.9.6）

**WebODM**（OpenDroneMap 的 Web 界面）开源免费，可一站式产出 DSM/DTM/DOM/点云。

1. 启动：`docker run -d -p 3000:3000 -v D:/webodm:/webodm_data --name webodm opendronemap/webodm:2.9.6`，浏览器访问 `http://localhost:3000`。
2. 新建项目 → 新建任务 → 上传全部影像。
3. 关键参数：
   - 坐标系：带坐标自动识别；无坐标选 `EPSG:32649`（郑州 WGS84/UTM 49N）。
   - 输出：勾选 **DSM、DTM、正射影像、点云(LAS)**。
   - 分辨率：DSM ≤ 1m（越高越细，耗时越长）。
4. 处理完成后，Downloads 下载：
   - ✅ **点云(LAS)** → `odm_georeferenced_model.laz`（核心，能量高度）
   - ✅ **正射影像** → `orthophoto.tif`（识别类型 + 核对底图）
   - ✅（若有）**DSM、DTM** → `dsm.tif`、`dtm.tif`（可直接差分）

## 四、详细技术方案

> 正射、倾斜、点云均来自 WebODM 已处理成果。4.1、4.2、4.3 分别独立实施，不融合。4.4 及后续原有内容和示例保留：nDSM 操作适用于高度栅格路线，正射和模型路线不强制执行。gis_obstacles 为原有入库结构示例，各路线实际使用自己的独立成果表。


### 4.1 正射影像障碍物提取入库详细步骤

> 以下 4.1.1～4.1.8 按实际操作顺序说明全流程；随后保留此前的能力边界、字段、验收及原有示例，供对照使用。全流程中的首次原始成果入库与提取后的结果入库是两个不同步骤。

#### 4.1.1 无人机航飞与原始影像整理

**本路线全流程**：大疆航飞影像 → WebODM 正射重建 → 下载正射 → QGIS 检查 → 原始影像及元数据入库 → 二维障碍物提取及结果入库 → 数据分析/API → Cesium 正射与二维轮廓展示。

1. 航前确定测区、目标地物和需要辨识的最小尺寸，依据相机、航高和目标分辨率设计航线。以覆盖屋顶及地表的下视影像为主，避免强逆光、运动模糊和大面积阴影。
2. 可将原方案航向重叠度不低于 80%、旁向不低于 60% 作为初始设计参考；建筑密集、起伏或遮挡区域应验证覆盖并提高重叠度，不能仅靠固定参数保证精度。
3. 导出原始 JPG 及 EXIF 定位信息；若使用 RTK/PPK 或像控点，保留对应资料、坐标基准和独立检查点。
4. 按架次整理目录，例如 D:\cc\drone\dom\flight_001\images；剔除失焦或损坏照片，保留原件和筛选清单。
5. 输出本阶段交付物：原始影像、测区范围、采集时间、相机资料、定位/像控资料。已有 WebODM 成果时可直接从下载检查阶段开始。

#### 4.1.2 WebODM 正射处理

1. 使用已正确部署的 WebODM，进入项目并新建任务，上传本架次影像；已有任务则核对任务记录，不重复创建。
2. 提交实际可用的像控或定位资料，确认其真实坐标系。无坐标的影像不能仅通过选择一个 EPSG 就获得可靠地理定位。
3. 以正射输出为本路线目标，根据样本任务设置 orthophoto-resolution，记录参数值及单位；所需分辨率不能超过原始影像可支撑的有效细节。
4. 执行影像匹配、相机解算、重建、正射投影与拼接。软件内部重建中间成果不代表下游要联合使用其他路线成果。
5. 处理结束检查报告、解算覆盖、影像空洞、边缘拉伸及检查点误差；局部失败应复核影像或补飞后重算。
6. 保存项目/任务 ID、WebODM 与处理引擎版本、参数和报告，作为后续数据批次标识。

#### 4.1.3 下载与成果归档

1. 在任务成果下载区下载正射 GeoTIFF，常见任务目录为 odm_orthophoto/odm_orthophoto.tif，实际压缩包名称和菜单以部署版本为准。
2. 不用无坐标的预览 JPG/PNG/WebP 替代 GeoTIFF 进行空间入库。
3. 下载处理报告及坐标资料，归档到 download、report、qgis、extract、publish 等目录，保留原始文件不覆盖。
4. 使用 GDAL 检查影像尺寸、波段、坐标系、像元大小、范围和 NoData：

~~~bat
gdalinfo D:\cc\drone\dom\flight_001\download\odm_orthophoto.tif
~~~

5. 建立文件清单及校验值，确认文件完整；影像与元数据必须能追溯到同一个正射任务。

#### 4.1.4 QGIS 加载、检查与准备

1. 打开 QGIS，在“数据源管理器 → 栅格”选择 GeoTIFF，或从浏览器面板拖入。
2. 在图层属性查看源坐标系和分辨率；项目坐标系按测区选择米制投影。项目动态显示转换不等于已转换源文件。
3. 检查 RGB 波段、透明 NoData、金字塔和不同缩放级别显示，圈定有效提取区域。
4. 如确需转换或裁剪，用“栅格 → 投影 → 变形/重投影”或对应处理算法输出新文件，保留原始影像。
5. 保存 QGIS 工程和处理参数；该阶段以检查和准备为主，正式提取在原始数据入库后执行。
6. 建立 PostgreSQL 连接：浏览器面板“PostgreSQL → 新建连接”，填写主机、端口、数据库和受限账户，测试连接后加载目标 schema。后续影像提取仍可读取已登记的文件，不要求模型从数据库二进制中读取影像。

#### 4.1.5 原始数据入库与结果表准备

**入库顺序**：先保存原始正射及来源，再执行提取，最后将提取对象写入结果表。影像可采用文件存储加数据库索引，也可实际导入 PostGIS Raster；不能把“影像登记”误认为已经有了障碍物轮廓。

~~~sql
CREATE SCHEMA IF NOT EXISTS dom;
CREATE TABLE dom.source_assets (
  id BIGSERIAL PRIMARY KEY,
  task_id TEXT NOT NULL UNIQUE,
  image_uri TEXT NOT NULL,
  source_srid INTEGER NOT NULL,
  capture_time TIMESTAMPTZ,
  imported_at TIMESTAMPTZ NOT NULL DEFAULT now(),
  metadata JSONB NOT NULL DEFAULT '{}'::jsonb
);
~~~

1. 向 source_assets 写入实际任务、资源地址、真实 SRID、采集时间及像元大小等元数据；采集时间未知时留空。
2. 大影像默认保存在服务器文件/对象存储，使用后端可访问的资源地址，不向浏览器返回本机 D 盘路径。
3. 如需将像元本身入库，先由数据库管理员启用 postgis 和 postgis_raster，再用 raster2pgsql 分块导入。以下在普通 cmd 执行，连接信息按项目修改；不加 -s 时从影像读取 SRID，入库后须核验是否正确：

~~~bat
raster2pgsql -I -C -M -t 256x256 "D:\cc\drone\dom\flight_001\download\odm_orthophoto.tif" dom.orthophoto_flight_001 | psql -h localhost -p 5432 -U gis_writer -d gis
~~~

4. 在 QGIS 刷新数据库连接，检查入库范围、波段、数量及资源引用。结果表单独命名 gis_obstacles_dom，字段说明见本节后面的保留内容。

#### 4.1.6 障碍物提取与结果入库

1. 读取已登记正射文件或数据库影像。小范围可新建 Polygon/MultiPolygon 图层人工勾绘；大范围先建立本区标注样本，再用验证通过的语义/实例分割模型输出掩膜。
2. 分块识别时留重叠边，合并掩膜后处理重复对象；不能直接将相邻屋顶全合成同一建筑。
3. 在 QGIS 处理工具箱搜索“多边形化/Polygonize”，将分类掩膜转为多边形；筛选目标类别，删除背景值。
4. 执行修复几何、必要的单部件拆分和人工编辑，保留对象编号、类别、轮廓含义、核验状态及任务 ID。
5. 建筑可见屋顶与落地轮廓分开标记；height、bottom_h、top_h 无可靠来源时全部为 NULL。
6. 导出到 PostGIS 临时表 dom.obstacles_stage，假设几何字段 geom，并包含 obstacle_type、outline_kind、review_status、task_id；用处理后的几何生成本路线正式结果：

~~~sql
CREATE TABLE gis_obstacles_dom AS
SELECT row_number() OVER ()::bigint AS id,
       task_id, obstacle_type, outline_kind, review_status,
       ST_Multi(ST_CollectionExtract(ST_MakeValid(geom), 3)) AS footprint,
       NULL::double precision AS height,
       NULL::double precision AS bottom_h,
       NULL::double precision AS top_h,
       now() AS imported_at
FROM dom.obstacles_stage
WHERE geom IS NOT NULL AND NOT ST_IsEmpty(geom);
ALTER TABLE gis_obstacles_dom ADD PRIMARY KEY (id);
CREATE INDEX idx_dom_footprint ON gis_obstacles_dom USING GIST (footprint);
~~~

此为首次建表示例；正式批次采用稳定对象 ID 和事务追加，生成后再次剔除修复产生的空几何。所有结果须处于本项目同一米制投影，再做距离/面积分析。

#### 4.1.7 数据分析、查询与后端服务

1. 按任务统计对象数量、类别占比、面积和核验状态；面积计算使用米制投影。
2. 对航线作水平缓冲，查询相交轮廓形成二维疑似冲突清单；高度未知返回“待核验”，不能判为三维安全。
3. 示例统计和参数化查询如下，:task_id、:route_wkt、:project_srid、:margin_m 为后端绑定参数，实际执行时由数据库驱动传入，不拼接用户输入：

~~~sql
SELECT obstacle_type, count(*) AS object_count,
       sum(ST_Area(footprint)) AS area_m2
FROM gis_obstacles_dom
WHERE task_id = :task_id
GROUP BY obstacle_type;

SELECT id, obstacle_type, review_status
FROM gis_obstacles_dom
WHERE task_id = :task_id
  AND ST_Intersects(
    footprint,
    ST_Buffer(ST_GeomFromText(:route_wkt, :project_srid), :margin_m)
  );
~~~

4. 建议提供 GET /api/dom/obstacles?bbox=...&taskId=... 和统计接口，使用空间索引、分页/数量上限，只返回视域内数据。
5. GeoJSON 接口返回标准 FeatureCollection，几何用 ST_AsGeoJSON(ST_Transform(footprint,4326))，属性包含 id、类别、任务和核验状态，原始库中几何保持项目投影。
6. 正射原始影像由 GeoServer 等发布为 WMS/WMTS，地图发布配置和数据库空间查询分开管理。

#### 4.1.8 Cesium 前端展示与验收

1. 先发布正射影像服务，确认其范围、坐标支持、跨域与鉴权；Cesium 不能直接把服务器 GeoTIFF 路径当作普通瓦片服务。
2. 用 WMS 影像提供器加载正射，再请求二维轮廓 GeoJSON；本路线不加载倾斜或点云。
3. 以下使用项目已兼容的 CesiumJS API，并假设已有 viewer；接口地址为示例，需由后端实现：

~~~js
viewer.imageryLayers.addImageryProvider(
  new Cesium.WebMapServiceImageryProvider({
    url: "/geoserver/dom/wms",
    layers: "dom:orthophoto_flight_001",
    parameters: { transparent: true, format: "image/png" }
  })
);
const domResponse = await fetch("/api/dom/obstacles?taskId=flight_001");
if (!domResponse.ok) throw new Error("DOM query failed");
const domData = await domResponse.json();
const domSource = await Cesium.GeoJsonDataSource.load(domData, {
  clampToGround: true,
  fill: Cesium.Color.YELLOW.withAlpha(0.25)
});
await viewer.dataSources.add(domSource);
await viewer.zoomTo(domSource);
~~~

4. 支持任务切换、类别过滤、对象点击和核验状态查看；高度未知只展示二维轮廓，不进行虚构高度拉伸。
5. 验收正射与轮廓是否错位、透明区是否正常、点击属性是否对应数据库、视域查询是否完整，以及移动/缩放时的加载性能。


技术参考：[ODM 成果说明](https://docs.opendronemap.org/outputs/)、[Cesium GeoJSON](https://cesium.com/learn/cesiumjs/ref-doc/GeoJsonDataSource.html)。

#### 4.1.9 输入与能力边界

输入为 WebODM 输出的正射影像，例如 GeoTIFF，名称以实际成果为准。检查覆盖范围、像元分辨率、坐标系和 NoData 区域。

普通正射影像用于识别建筑屋顶、树冠、构筑物等可见地物的二维范围，不能直接从像元颜色得到真实建筑高度。屋顶轮廓也不必然等于建筑落地轮廓，应记录轮廓含义。

本路线不调用点云、倾斜模型或 DSM/DTM。无法可靠获得的高度、底部高程和顶部高程保留为空。

#### 4.1.10 技术流程

```text
WebODM 正射影像
  → 影像质量与坐标检查
  → 人工勾绘或影像分割生成候选掩膜
  → 矢量化、单体拆分、轮廓修正
  → 类别与轮廓语义核对
  → gis_obstacles_dom 独立入库
```

1. 在 QGIS 加载正射影像，选择适合项目区域、以米为单位的投影坐标系进行面积计算和编辑。
2. 小范围可人工勾绘；大范围可采用经项目样本验证的建筑或地物分割模型，不默认现有模型适用于本区域。
3. 将掩膜转为多边形，修复无效几何，拆分相连对象，检查阴影、树冠遮挡及道路误识别。
4. 填写类别、轮廓含义、核验状态和可用的置信度，无法识别的类别标为未知。
5. 通过 QGIS 的 PostGIS 导入功能，将核验后的矢量成果写入独立表，并建立轮廓空间索引。

#### 4.1.11 入库字段

| 字段 | 含义 |
|---|---|
| `id` / `footprint` | 主键、二维 Polygon/MultiPolygon 轮廓 |
| `obstacle_type` / `outline_kind` | 地物类别、屋顶或树冠等轮廓含义 |
| `height` / `bottom_h` / `top_h` | 本路线无可靠来源时均为 NULL |
| `confidence` / `review_status` | 置信度、人工核验状态 |
| `image_uri` / `source_task_id` | 原始正射资源引用、来源任务 |
| `capture_time` / `imported_at` | 采集时间、入库时间 |

原始影像可保存于文件存储，数据库记录资源地址；需要地图展示时独立发布影像服务。

#### 4.1.12 交付与验收

交付二维轮廓图层、分类属性、来源记录及抽样核验结果，核验轮廓位置、单体完整性、误检和漏检。结果可作为二维禁入范围或人工审核参考；高度未知的记录不能作为已完成三维净空验证的依据。

### 4.2 倾斜三维模型障碍物提取入库详细步骤

> 以下 4.2.1～4.2.8 按实际操作顺序说明全流程；随后保留此前的能力边界、字段、验收及原有示例，供对照使用。全流程中的首次原始成果入库与提取后的结果入库是两个不同步骤。

#### 4.2.1 无人机倾斜航飞与影像整理

**本路线全流程**：大疆倾斜航飞影像 → WebODM 三维重建 → 下载模型、纹理与定位资料 → QGIS 空间检查及三维工具配合 → 模型资源入库 → 单体障碍物提取及结果入库 → 三维范围分析/API → Cesium 模型与提取对象展示。

1. 根据建筑高度、街区密度、目标立面和安全航高规划航线，采用多镜头倾斜或多方向拍摄，保证同一建筑有多个方向的有效观测。
2. 检查下视和倾斜影像覆盖，必要时补充交叉航线，避免只有屋顶而没有足够立面信息。
3. 高楼密集、深街巷等遮挡区域单独检查；相机姿态和曝光参数以实际载荷、航速及场景试飞结果确定。
4. 原始 JPG、POS/EXIF、RTK/PPK、像控和检查点资料分目录整理，保留镜头及架次信息。
5. 输出本阶段交付物：完整倾斜影像、测区范围、采集批次、定位资料和质量检查记录。

#### 4.2.2 WebODM 三维重建

1. 在 WebODM 项目新建倾斜任务，上传该任务的有效影像和定位资料，记录镜头、架次及坐标基准。
2. 确认没有开启跳过三维模型的选项；按场景设置重建质量、网格细节和纹理质量，先用小测区验证内存、耗时及细节效果。
3. 执行匹配、相机解算、密集重建、网格生成和纹理映射，检查处理日志。
4. 预览楼顶、立面、屋檐与地面接缝，检查网格孔洞、漂浮面、扭曲及纹理错位。
5. 重建成功不等于已经识别建筑单体；WebODM 交付的是场景模型，后续仍须对象提取。
6. 保存任务 ID、版本、参数、报告与定位信息；不要将“模型看起来正常”作为高程和定位已验收的结论。

#### 4.2.3 下载模型及配套文件

1. 下载任务提供的纹理模型压缩包，若界面未提供所需文件，由有权限的管理员从任务成果目录导出完整成果。
2. 常见成果位于 odm_texturing，包含 OBJ、MTL 和纹理图片；地理定位模型可能为 odm_textured_model_geo.obj，具体以实际任务为准。
3. 保持模型、材质和纹理的相对路径，不能只下载 OBJ 而遗漏 MTL/图片。
4. 一并归档坐标系、局部原点或偏移量等定位资料；即使文件名带 geo，也须核对其单位和坐标约定。
5. 在 MeshLab 或 Blender 中打开文件，确认模型可读、纹理齐全。归档原模型与后续派生模型，记录文件清单及校验值。

#### 4.2.4 QGIS 使用与三维工具衔接

1. 在 QGIS 建立本路线独立工程，设置项目投影并连接 PostgreSQL。
2. 不假定当前 QGIS 版本能直接完整显示带纹理 OBJ 或对其进行建筑单体分割；先检查格式和驱动支持，不能将 OBJ 当作 Shapefile 导入。
3. 使用 MeshLab/Blender 等读取三维网格，依据模型自身定位信息产生可在 QGIS 使用的覆盖边界、候选轮廓或标记点，保存为 GeoPackage 等空间格式。
4. 这里的边界只是模型范围/待提取范围，不提前当作已经确认的建筑成果；文件需写入正确坐标系和对象标识。
5. 在 QGIS 加载这些模型派生数据，检查测区范围、坐标单位、地理位置，必要时与项目已有控制点核对定位，不能用未知偏移强行拖拽“看齐”。
6. 原始网格的选面、切分和顶点统计在三维工具或模型处理脚本中执行，QGIS 负责其派生矢量的校核、属性编辑、空间分析和数据库连接。
7. 保存坐标变换记录，确保模型工具与 QGIS 使用同一地理定位定义。

#### 4.2.5 模型资源入库与提取任务登记

1. 按任务将模型、纹理、定位资料上传到文件/对象存储，形成可追溯资源包。
2. 在数据库登记原始资源、任务、坐标和处理状态。这里“模型入库”指资源及元数据纳管，不是将 OBJ 文件强制转成二维 PostGIS 几何。
3. 建立独立资源表：

~~~sql
CREATE SCHEMA IF NOT EXISTS mesh;
CREATE TABLE mesh.source_assets (
  id BIGSERIAL PRIMARY KEY,
  task_id TEXT NOT NULL UNIQUE,
  model_uri TEXT NOT NULL,
  source_srid INTEGER,
  transform_info JSONB NOT NULL DEFAULT '{}'::jsonb,
  capture_time TIMESTAMPTZ,
  imported_at TIMESTAMPTZ NOT NULL DEFAULT now(),
  process_status TEXT NOT NULL DEFAULT 'REGISTERED'
);
~~~

4. transform_info 保存经核验的局部到项目坐标变换、轴向、单位及高程基准；定位尚不明确的任务保持待定位状态，不执行正式空间分析。
5. 后台提取任务按资源表读取已入库模型包，将过程记录与 task_id 关联；失败可重试且不覆盖原始文件。

#### 4.2.6 模型障碍物单体提取与结果入库

1. 读取已登记模型，按空间范围分块，建立面片与对象的对应关系。
2. 小测区人工选择屋顶和立面面片、分离对象；自动化可按法向、平面结构、纹理及邻接关系生成候选，再对本项目样本验证。
3. 建筑和地面常连成一张网格，不能把连通块直接当建筑。对相邻建筑粘连、孔洞和缺失立面作人工复核。
4. 为每个核验对象生成水平投影轮廓，保留挑檐和悬挑范围，并记录 object_id 关联原模型。
5. 清除异常顶点后统计顶部高程；仅用模型本身可确认的地面/底部确定 bottom_h，无法确认时 height 和 bottom_h 留空。
6. 在 QGIS 加载对象轮廓，修复几何并编辑类别、核验状态、统计方法；导入 mesh.obstacles_stage。
7. 临时表约定字段为 task_id、object_id、geom、obstacle_type、top_h、bottom_h、review_status，正式表首次建立示例：

~~~sql
CREATE TABLE gis_obstacles_mesh AS
SELECT row_number() OVER ()::bigint AS id,
       task_id, object_id, obstacle_type, review_status,
       ST_Multi(ST_CollectionExtract(ST_MakeValid(geom), 3)) AS footprint,
       top_h, bottom_h,
       CASE WHEN top_h IS NOT NULL AND bottom_h IS NOT NULL
                 AND top_h >= bottom_h
            THEN top_h - bottom_h END AS height
FROM mesh.obstacles_stage
WHERE geom IS NOT NULL AND NOT ST_IsEmpty(geom);
ALTER TABLE gis_obstacles_mesh ADD PRIMARY KEY (id);
CREATE INDEX idx_mesh_footprint ON gis_obstacles_mesh USING GIST (footprint);
~~~

8. 检查空几何、负高度、异常值及来源关联，复核后标记任务完成。增量批次采用事务和稳定对象 ID。

#### 4.2.7 数据分析与接口服务

1. 查询建筑/构筑物数量、投影面积、高度分布及高度缺失率，区分已核验与待核验对象。
2. 水平避障先对轮廓与航段缓冲区作相交筛选；高度完整对象再判断航段高程区间与障碍物区间是否冲突。
3. 单个航段内高度变化较大时应进一步分段或沿交点求高度，不能只比较整个航线最低和最高值就作为精确结论。
4. 示例为水平范围内的粗筛，并非完整飞行安全判定。参数由后端绑定，轮廓与航段采用一致米制投影、高程使用一致基准：

~~~sql
SELECT id, object_id, top_h, bottom_h, height
FROM gis_obstacles_mesh
WHERE task_id = :task_id
  AND review_status = 'VERIFIED'
  AND bottom_h IS NOT NULL AND top_h IS NOT NULL
  AND ST_Intersects(footprint,
      ST_Buffer(ST_GeomFromText(:segment_wkt, :project_srid), :horizontal_margin_m))
  AND top_h + :vertical_margin_m >= :segment_min_h
  AND bottom_h - :vertical_margin_m <= :segment_max_h;
~~~

5. 未知高度对象另行返回待核验清单，不因上面 SQL 未命中就视为没有障碍物。
6. 提供 /api/mesh/obstacles、/api/mesh/analysis、/api/mesh/tileset 等接口，轮廓按视域查询并转为 4326 GeoJSON；模型资源通过 HTTP 静态服务或受控资源服务发布。

#### 4.2.8 Cesium 模型展示与对象查询

1. 将原模型转换为带正确地理定位、层级细节和包围体的 3D Tiles。转换工具需在项目样本验证格式、纹理、定位和性能，不假定 WebODM 导出包已是 3D Tiles。
2. 对局部坐标模型，转换时写入正确的定位变换；不得重复应用原点偏移或将米制投影坐标直接当作 ECEF 坐标。
3. 需要按模型点击获取单体属性时，切片阶段应保留 object_id 等要素元数据；未实现单体元数据时，用独立轮廓图层作为可点击对象。
4. 当前 CesiumJS 加载示例：

~~~js
const meshTiles = await Cesium.Cesium3DTileset.fromUrl(
  "/data/mesh/flight_001/tileset.json"
);
viewer.scene.primitives.add(meshTiles);
await viewer.zoomTo(meshTiles);
const meshResponse = await fetch("/api/mesh/obstacles?taskId=flight_001");
if (!meshResponse.ok) throw new Error("Mesh query failed");
const meshSource = await Cesium.GeoJsonDataSource.load(await meshResponse.json(), {
  clampToGround: false
});
await viewer.dataSources.add(meshSource);
~~~

5. 文档原环境列出的 Cesium 1.91/1.92 不直接套用现代 fromUrl；旧版沿用 4.7 中构造方式并等待 readyPromise。项目应统一所选版本，不能混用两代初始化 API。
6. 三维轮廓白膜的 height 使用已转换到 Cesium 高程基准的底部高程，extrudedHeight 使用同一基准顶部高程；不能把相对 height 当成绝对顶部。后端应明确输出 bottom_ellipsoid_h、top_ellipsoid_h 或提供等价的显式转换结果。
7. 底部未知时不生成虚构白膜，可仅显示原模型和独立对象查询结果。若要轮廓贴到模型上，需验证所用贴附能力，不假定贴地一定等于贴模型。
8. 验收纹理、定位、高程、近远层级、点击关联、视域过滤和加载性能。


技术参考：[ODM 模型成果](https://docs.opendronemap.org/outputs/)、[Cesium 3D Tiles 加载](https://cesium.com/learn/cesiumjs/ref-doc/Cesium3DTileset.html)。

> 以下为此前保留的说明与示例；涉及操作顺序时以上述八阶段为准。


#### 4.2.9 输入与能力边界

输入为 WebODM 输出的倾斜三维网格模型及其纹理、定位信息。以实际模型格式为准，确认模型采用地理坐标还是局部坐标，以及轴向、单位、平移量和高程基准。

本路线只处理模型本身，不调用正射影像分类，也不调用点云生成地面。模型不是 DSM，不能直接套用 DSM−DTM 的栅格差分流程。

模型顶点可提供表面三维位置，但建筑底部可能被遮挡或与地面连接。不能确认地面的对象，只记录可确认的顶部高程或模型范围，底部高程与相对高度保持为空。

#### 4.2.10 技术流程

```text
WebODM 倾斜三维模型
  → 模型、纹理与定位检查
  → 网格分区、障碍物单体分割
  → 单体水平投影轮廓与高程统计
  → 模型可见地面核验、属性检查
  → gis_obstacles_mesh 独立入库
```

1. 在支持实际格式的三维工具中加载模型，确认纹理、比例和地理位置正确。
2. 小范围人工选取、切分单体；自动化时可根据网格连通性、法向、平面特征及纹理生成候选对象，再人工核验。建筑和地面可能连续相连，不能仅凭连通分量认定建筑单体。
3. 对核验后的障碍物网格生成水平投影轮廓，按模型可见范围保留挑檐、悬挑等结构，记录为模型投影轮廓。
4. 剔除明显漂浮面和异常顶点后统计顶部高程。仅在模型自身存在可确认地面或建筑底部时填写 `bottom_h`，计算 `height = top_h - bottom_h`。
5. 标记孔洞、遮挡、单体粘连和底部缺失等问题，将核验后的轮廓与属性导入独立表，建立空间索引。

#### 4.2.11 入库字段

| 字段 | 含义 |
|---|---|
| `id` / `footprint` | 主键、单体水平投影轮廓 |
| `obstacle_type` | 模型形态或人工核验确定的类别 |
| `top_h` / `bottom_h` / `height` | 顶部高程、可确认的底部高程、相对高度 |
| `height_status` / `review_status` | 高度完整性、核验状态 |
| `model_uri` / `object_id` | 模型资源引用、单体标识 |
| `source_task_id` / `capture_time` / `imported_at` | 来源任务、采集时间、入库时间 |

大型网格和纹理文件保存于文件或对象存储，PostGIS 保存可查询的轮廓、属性和资源引用，不把原始网格直接作为普通二维矢量图层导入。

#### 4.2.12 交付与验收

交付模型障碍物轮廓、单体引用、高程属性和缺失说明，核验定位、单体分割和高程完整性。三维展示时按实际格式另行转换为 Cesium 可加载的资源，例如 3D Tiles，并验证定位。展示格式转换不等于完成障碍物提取。

### 4.3 点云障碍物提取入库详细步骤

> 以下 4.3.1～4.3.8 按实际操作顺序说明全流程；随后保留此前的能力边界、字段、验收及原有示例，供对照使用。全流程中的首次原始成果入库与提取后的结果入库是两个不同步骤。

#### 4.3.1 无人机航飞与摄影测量点云生产准备

**本路线全流程**：大疆航飞影像 → WebODM 密集重建 → 下载 LAS/LAZ → QGIS 点云检查 → 点云资源及元数据入库 → 地面分类/高度分析/障碍物提取及结果入库 → 分析/API → Cesium 点云与障碍物展示。

1. 本路线原始输入通常是航飞照片，点云由 WebODM 摄影测量生成，不是默认由机载激光雷达直接采集。
2. 根据目标尺寸、地形和遮挡情况设计影像分辨率、多视角及重叠度，检查屋顶、地面和杆塔区域的有效观测。
3. 低纹理、反光、水体、植被晃动和遮挡会影响重建质量，重点区域先试飞验证；不能仅提高软件质量参数补回未拍到的地面。
4. 整理原始影像、定位/像控、采集时间和测区范围，保留架次及任务记录。
5. 已有 WebODM 点云时不重复航飞处理，从下载验收开始，并补齐来源资料。

#### 4.3.2 WebODM 点云重建

1. 新建点云任务或核对已有任务，上传有效影像和定位资料。
2. 根据影像和资源条件选择点云质量，例如 pc-quality；检查处理流程没有跳过所需密集重建阶段。
3. 默认成果可能为 LAZ；需要 LAS 时根据部署引擎检查 pc-las 等实际支持选项，LAZ 与 LAS 均可作为本路线输入。
4. 执行匹配、解算、密集重建和地理配准，检查空洞、点密度、漂浮噪声和测区边缘覆盖。
5. 地面分类如已执行，也须检查 Classification 的含义与有效性，不能默认所有“分类字段存在”的文件就能直接生成可靠 DTM。
6. 记录引擎版本、任务参数、坐标和高程基准、报告及质量问题。下游仅消费点云，不要求下载正射和倾斜模型。

#### 4.3.3 下载与点云验收

1. 下载地理配准点云，常见路径为 odm_georeferencing/odm_georeferenced_model.laz，实际文件名以任务为准。
2. 下载报告、分类说明与坐标资料，将下载原件设为归档版本，后续去噪和分类输出新文件。
3. 在 OSGeo4W Shell 或已正确配置 PDAL 的终端检查：

~~~bat
pdal info --metadata "D:\cc\drone\cloud\flight_001\download\odm_georeferenced_model.laz"
~~~

4. 核对点数、范围、XYZ 单位、分类和 RGB 等维度、比例因子及坐标系统；若只有局部坐标，先完成定位。
5. 保存清单、校验值与验收结论，明显错误的范围或坐标不能通过简单修改 SRID 解决。

#### 4.3.4 QGIS 点云使用与质量检查

1. 在 QGIS 数据源管理器中选择点云，加载 LAS/LAZ。首次加载可能建立空间索引，应保证缓存目录可写并等待完成。
2. 使用 RGB、Z 高程或 Classification 渲染检查表面和地面，查看图层元数据及识别工具读取点属性。
3. 打开三维地图视图，检查建筑、地面起伏、漂浮点、孔洞和边缘断层；不要把地面缺点的区域当作地面高度为零。
4. 框选或建立待处理区域边界并保存 QGIS 工程，记录稀疏点和重点复核区域。
5. QGIS 用于浏览和派生结果检查；去噪、SMRF、点级离地高度等工作使用当前版本实际可用的处理算法，或外部 PDAL/CloudCompare。
6. 本文原环境 QGIS 3.30 不默认具备新版文档的全部点云算法；无法执行时使用外部工具输出结果后再加载检查。

#### 4.3.5 点云资源入库及任务管理

1. 将原始 LAZ/LAS 上传到服务器文件或对象存储，登记 task_id、资源地址、点数、坐标和采集时间。
2. 采用“文件存储 + PostGIS 元数据”作为基础路线；直接将 LAZ 拖到普通 PostGIS 矢量导入窗口不等于点云已转换为可查询点对象。
3. 建立资源表，后续提取任务从该表领取输入：

~~~sql
CREATE SCHEMA IF NOT EXISTS cloud;
CREATE TABLE cloud.source_assets (
  id BIGSERIAL PRIMARY KEY,
  task_id TEXT NOT NULL UNIQUE,
  cloud_uri TEXT NOT NULL,
  source_srid INTEGER NOT NULL,
  point_count BIGINT,
  capture_time TIMESTAMPTZ,
  imported_at TIMESTAMPTZ NOT NULL DEFAULT now(),
  process_status TEXT NOT NULL DEFAULT 'REGISTERED',
  metadata JSONB NOT NULL DEFAULT '{}'::jsonb
);
~~~

4. 如要求每个点都在数据库中可查询，应单独设计点云专用存储扩展或分块点表、索引和容量方案，不将数亿点直接写入普通业务障碍物表。本方案默认不要求点级数据库存储。
5. 初始化 gis_obstacles_cloud 的结果字段约定，记录提取批次、参数及作业状态；原始资源登记成功后才启动提取。

#### 4.3.6 点云障碍物提取、派生栅格入库与结果入库

1. 用 PDAL 等去除明显离群点，输出 clean.laz，保留原始文件。
2. 对未可靠分类的数据执行 SMRF 等地面分类，输出 classified.laz。在 QGIS 按 Classification 检查地面点，不执行“全部点赋为地面”。
3. **点级路径**：依据同一点云的可靠地面计算离地高度，筛选目标高度范围后聚类，生成对象轮廓和高程统计；保存阈值与聚类参数。
4. **栅格路径**：表面点生成 DSM，地面点生成 DTM，统一网格后计算未阈值化 nDSM。地面缺失处保留 NoData，再单独生成二值候选掩膜。
5. 将派生高度栅格先导入本路线 schema，随后在数据库内提取对象；此处仅在确需 Raster 时启用 postgis_raster：

~~~bat
raster2pgsql -I -C -M -t 256x256 "D:\cc\drone\cloud\flight_001\extract\ndsm.tif" cloud.ndsm_flight_001 | psql -h localhost -p 5432 -U gis_writer -d gis
~~~

6. 在 QGIS 栅格计算器生成高度掩膜并多边形化，或用 PostGIS Raster 在库内操作。下面为首次建表的候选提取示例，1.5 米仅为试验阈值；先按分块转多边形，再合并分块边界上的相邻候选：

~~~sql
CREATE TABLE cloud.candidates_flight_001 AS
WITH mask_parts AS (
  SELECT p.geom
  FROM cloud.ndsm_flight_001 r
  CROSS JOIN LATERAL ST_DumpAsPolygons(
    ST_Reclass(r.rast, 1, '[-10000-1.5]:0,(1.5-10000]:1', '8BUI', 0), 1, true
  ) p
  WHERE p.val = 1
), merged AS (
  SELECT ST_UnaryUnion(ST_Collect(geom)) AS geom FROM mask_parts
)
SELECT row_number() OVER ()::bigint AS id, d.geom
FROM merged
CROSS JOIN LATERAL ST_Dump(merged.geom) d;
~~~

7. 上述范围是假定的样本高度范围，应按实际数据扩展；生产任务分区合并以控制内存。相连建筑可能被合为一个候选，仍需单体拆分，不能直接作为完成识别的建筑。
8. 对候选用原始 nDSM、DSM、DTM 或点云统计 height、top_h、bottom_h；插值地面须记录估计质量。不要只用二值掩膜值 1 作为高度。
9. 在 QGIS 校核轮廓和属性，按类别分别设置面积/点数过滤。导入 cloud.obstacles_stage，字段含 task_id、geom、obstacle_type、bottom_h、top_h、height、height_method、ground_status、review_status。
10. 建立独立结果表 gis_obstacles_cloud，几何修复及空间索引参照 4.1 的方式，但保留此路线的真实高度字段，不将其设为 NULL；增量使用稳定 ID、事务和批次字段。
11. 原有 DSM/DTM 概念和命令在本节末尾保留。附录 A 原例中的强制 Classification=2 会破坏地面筛选，实际应删除该强制赋值及其不必要的分类搬运步骤，使用核验后的分类结果。

#### 4.3.8 Cesium 点云、障碍物和分析结果展示

1. 将 LAZ/LAS 用验证过的点云切片工具转换成 Cesium 可加载的点云 3D Tiles，配置正确定位、包围体、层级细节和点属性。
2. QGIS 可读取的 LAS/LAZ、EPT 或其本地索引，不应直接当作 Cesium 3D Tiles 地址；前端需与具体发布格式匹配。
3. 通过 HTTP 发布 tileset.json 和内容文件，检查鉴权、跨域、缓存及资源路径。加载示例使用现代 API；原环境旧版本按 4.2 的兼容说明处理：

~~~js
const cloudTiles = await Cesium.Cesium3DTileset.fromUrl(
  "/data/cloud/flight_001/tileset.json"
);
viewer.scene.primitives.add(cloudTiles);
await viewer.zoomTo(cloudTiles);
const cloudResponse = await fetch("/api/cloud/obstacles?taskId=flight_001");
if (!cloudResponse.ok) throw new Error("Cloud query failed");
const cloudSource = await Cesium.GeoJsonDataSource.load(await cloudResponse.json(), {
  clampToGround: false
});
await viewer.dataSources.add(cloudSource);
for (const entity of cloudSource.entities.values) {
  if (!entity.polygon) continue;
  const values = entity.properties.getValue(viewer.clock.currentTime);
  const bottom = values.bottom_ellipsoid_h;
  const top = values.top_ellipsoid_h;
  if (Number.isFinite(bottom) && Number.isFinite(top) && top >= bottom) {
    entity.polygon.height = bottom;
    entity.polygon.extrudedHeight = top;
    entity.polygon.material = Cesium.Color.ORANGE.withAlpha(0.35);
  } else {
    entity.show = false; // 缺失高程的对象另列待核验清单
  }
}
~~~

5. 白膜以轮廓和高程区间表达近似体，不等于保留了点云中的悬挑、桥下空间等完整三维结构。

#### 4.3.9 输入与能力边界

输入为 WebODM 输出的 LAS/LAZ 点云，例如 `odm_georeferenced_model.laz`。检查点数、覆盖、密度、坐标系、单位及分类字段，不能默认已有可靠的地面分类。

本路线不调用正射影像或倾斜模型。所需 DSM、DTM、nDSM 均由本路线自身的点云派生。摄影测量点云不等同于激光雷达点云，遮挡处地面及细电线可能缺失，提取完整性受原始点云质量限制。

#### 4.3.10 技术流程

```text
WebODM LAS/LAZ 点云
  → 数据检查、异常点清理
  → 地面分类、地面覆盖检查
  → 自身点云派生 DSM/DTM 或点级离地高度
  → 高度筛选、聚类或掩膜矢量化
  → 轮廓、高程及类别核验
  → gis_obstacles_cloud 独立入库
```

1. 使用 PDAL、QGIS 或点云工具检查数据，去除明显异常点；分块处理时保留边界重叠区，最终去重。
2. 对未可靠分类的点云进行地面滤波，例如 SMRF，并抽样核验。仅将真实地面分类点用于 DTM，不能把全部点强制标为地面。
3. **栅格路径**：由清理后的表面点生成 DSM，由地面点插值生成 DTM。两者坐标系、分辨率、范围及网格原点一致后，计算 `nDSM = DSM - DTM`。无有效地面支撑的区域保留为未知。
4. **点级路径**：根据同一点云的地面估计计算离地高度，对高于阈值的点聚类并生成轮廓。可减少栅格化细节损失，但仍受原始点云密度限制。
5. 高度阈值、最小面积及聚类距离按目标类型和密度配置。1.5 米、10 平方米仅作试验参数，不能统一剔除杆塔等小面积目标。
6. 统计对象地面高程、顶部高程与相对高度，记录统计方法。类别根据几何特征或经验证的点云分类模型确定，无法确认时标为未知，不只按高度和面积认定建筑。
7. 将核验后的对象轮廓与统计属性导入独立表，建立轮廓空间索引。

#### 4.3.13 原有高度模型构建（nDSM）

**概念**：
- **DSM**（数字表面模型）= 地物顶部高程（含建筑、树顶）。
- **DTM**（数字地面模型）= 裸地面高程（滤波去掉地物）。
- **nDSM = DSM − DTM** = 每个像素"地物高出地面多少米"，是提取障碍物的依据。

**两条获取路径（二选一）**：

**路径 A：WebODM 直接给 DSM/DTM**（最省事）
```
直接下载 dsm.tif 和 dtm.tif，做差分即可。
```

**路径 B：用点云生成（无 DSM/DTM 时）**
在 OSGeo4W Shell 中：
```bash
# ① DSM：全部点取最高（含楼顶）
pdal translate odm_georeferenced_model.laz dsm.tif -w gdal \
  --writers.gdal.resolution=0.5 --writers.gdal.output_type=max

# ② DTM：地面滤波只留地面点 → 裸地面（dem.json，见附录 A）
pdal pipeline dem.json
```

**差分得到 nDSM**：
```bash
gdal_calc.py -A dsm.tif -B dem.tif --outfile=ndsm.tif \
  --calc="numpy.where(A-B>1.5, A-B, 0)" \
  --NoData=-9999 --type=Float32
```
参数含义：`A−B` 逐像素算 `DSM−DTM`；`>1.5m` 保留高度值（障碍物），否则记 0；`Float32` 保留小数高度。

> 若直接用 WebODM 的 DSM/DTM，命令改为 `gdal_calc.py -A dsm.tif -B dtm.tif ...`。

### 4.4 障碍物提取与矢量化（PostGIS）

把高度图 `ndsm` 变成障碍物轮廓多边形：

```sql
-- ① 高度阈值二值化 + 多边形化（相邻高像素合并成块）
CREATE TABLE obs_tmp AS
WITH polys AS (
  SELECT (ST_Dump(ST_Polygonize(ST_Union(ST_AsBinary(
           ST_Reclass(rast, 1, '[1.5-9999]:1', '8BUI', 0)
         ))))).geom AS geom
  FROM ndsm
)
SELECT row_number() OVER () AS id, geom FROM polys;

-- ② 取每区域最高高度 + 过滤碎块（<10㎡ 的噪声剔除）
CREATE TABLE obs_cand AS
SELECT t.id, t.geom, round(MAX(p.val)::numeric,2) AS height
FROM obs_tmp t
CROSS JOIN LATERAL (
   SELECT (ST_PixelAsPoints(ST_Clip(r.rast, t.geom))).val AS val
   FROM ndsm r WHERE ST_Intersects(r.rast, t.geom)
) p
GROUP BY t.id, t.geom
HAVING MAX(p.val) > 1.5 AND ST_Area(t.geom) > 10;

-- ③ 类型判定（高度 × 面积，无需正射）
ALTER TABLE obs_cand ADD COLUMN obstacle_type TEXT;
UPDATE obs_cand SET obstacle_type = CASE
  WHEN height > 15 AND ST_Area(geom) > 100 THEN 'BUILDING'   -- 高+大=楼
  WHEN height > 15 THEN 'TOWER_POLE'                          -- 高+小=杆/塔
  WHEN height > 3  THEN 'TALL_OBSTACLE'                       -- 中=树/构筑物
  ELSE 'LOW_OBSTACLE' END;
```

### 4.6 规划应用（净空/避障）

```sql
-- 航段净空检查：障碍物外扩 5m，检测是否与航段相交
SELECT o.id, o.obstacle_type, o.height,
       ST_3DDistance(p.geom, ST_Force3D(o.footprint)) AS dist
FROM gis_obstacles o, gis_flight_paths p
WHERE p.id = 1001
  AND ST_3DIntersects(ST_Buffer(ST_Force3D(o.footprint), 5), p.geom);
```
- 与 `gis_flight_paths`、`gis_electric_fence`、`gis_astar_3d_flight_plan` 联动，构成"航迹规划 + 净空避障 + 围栏管控"闭环。
- 可按需过滤：只查建筑 `WHERE obstacle_type='BUILDING'`；只查超过某高度 `WHERE height>10`。

### 4.7 三维可视化叠加（Cesium）

**前提**：`gis_obstacles` 导出前统一转 **EPSG:4326**（Cesium 用 WGS84 经纬度），否则与倾斜模型错位。

**三种叠加方式（按需选）**：

**方式 A：GeoJSON + Cesium 前端拉伸白膜（最快）**
```sql
-- 导出（转 4326）
SELECT ST_AsGeoJSON(ST_Transform(footprint,4326))::jsonb
       || jsonb_build_object('height',height,'type',obstacle_type)
FROM gis_obstacles;
```
```js
const viewer = new Cesium.Viewer('cesiumContainer');
viewer.scene.primitives.add(new Cesium.Cesium3DTileset({ url: '.../tileset.json' })); // 倾斜模型

const ds = await Cesium.GeoJsonDataSource.load('obstacles.geojson', { clampToGround: false });
for (let e of ds.entities.values) {
  if (e.polygon) {
    e.polygon.material = Cesium.Color.Yellow.withAlpha(0.6);
    e.polygon.height = 0;
    e.polygon.extrudedHeight = e.properties.height.getValue(); // 拉伸成障碍物高度
  }
}
viewer.dataSources.add(ds);
```

**方式 B：GeoServer 发布**（动态更新、在线查询属性）
- 发布 `gis_obstacles` 为 WMS/WFS，Cesium 用 `WebMapServiceImageryProvider` 或 WFS 加载。

**方式 C：pg2b3dm 转 3D Tiles**（与倾斜模型统一渲染管线）
```bat
pg2b3dm -i "host=localhost user=postgres password=xxx dbname=gis" \
  -t gis_obstacles -c height -o D:\cc\drone\obstacle_tiles --maximumLevel 5
```

| 8 | Cesium 叠加 | Cesium | 倾斜模型+障碍物白膜 |

## 八、质量控制与运维

1. **坐标系统一**：raster2pgsql 的 `-s`、建表 SRID、Cesium 4326 三处对齐，否则与已有数据失配。
2. **分辨率一致**：DSM/DTM 分辨率必须相同（都用 0.5），否则差分出错。
3. **阈值参数化**：高度阈值 1.5m、面积 10㎡ 按任务动态调；抽样核对。
4. **目视核对**：QGIS 加载 nDSM + DOM，核对漏判（屋顶抹平）、误判（停车场/阴影）。
5. **细小物局限**：细电线杆、稀疏小树易被 DSM 平滑漏判；安全敏感场景用点云路线。
6. **增量更新**：复飞后 `TRUNCATE` 重灌该架次，保留 `flight_time` 版本对比。
7. **索引维护**：大库按 `source`/`flight_time` 分区。

### 附录 B：常见问题排查

### 附录 C：净空/避障查询
```sql
SELECT o.id, o.obstacle_type, o.height,
       ST_3DDistance(p.geom, ST_Force3D(o.footprint)) AS dist
FROM gis_obstacles o, gis_flight_paths p
WHERE p.id = 1001
  AND ST_3DIntersects(ST_Buffer(ST_Force3D(o.footprint), 5), p.geom);
```
